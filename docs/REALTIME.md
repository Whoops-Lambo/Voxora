# Live updates, presence and notification sounds

Everyone who wants to chat together must connect to **https://voxora-public.onrender.com** (or the same other shared backend). User Settings → Server Connection displays the current address and installation ID. A local workspace is a separate installation on one PC. The Windows app offers Join Public Voxora; local accounts and messages remain on the PC, and public accounts are separate.

The connection button opens Server Connection. **Live** means the event stream is delivering updates. **Syncing** means HTTP catch-up is working while the event stream recovers. **Offline** means requests failed; Voxora retries with a bounded delay. Retry Live Sync, bringing the window forward, or reconnecting the network requests another check. Calls still require the live signaling connection; rejoin after it recovers.

The backend sends flushed, unbuffered event-stream headers and a data heartbeat. Active HTTP clients have short, authenticated presence leases, so blocked event streams do not make everyone appear offline. Leases expire after 30 seconds without renewal, or immediately when their session logs out or the account is suspended. Invisible users continue to appear offline. Presence leases are held in memory and do not rewrite chat storage on each heartbeat.

HTTP catch-up uses session-authenticated `GET /api/sync?after=<messageSequence>&threadAfter=<threadSequence>`. It returns up to 100 accessible new messages and 100 accessible thread replies, `next`, `threadNext` and `hasMore`. Private-channel access, thread access and blocking are checked for every response. Anonymous access returns 401. Positions must be nonnegative integers; a position ahead of the installation returns 409. Clients keep their own cursors, never use another installation's cursors, and begin at the current position when signing in so old history does not trigger new alerts. Current channel snapshots also repair edits/deletions. Historical message views and drafts are preserved.

Message sounds default on for devices without a saved preference. Existing explicit opt-outs stay off. Open User Settings → Notifications to change Message sounds and Play Test Sound. DMs have a two-tone ping; personal, role, @here and @everyone mentions use a higher two-tone ping. Notification policy, mute, blocks, DND and active viewing still apply. Bursts are coalesced, server-resolved mention recipients remain authoritative, and already-delivered messages are not sounded again during catch-up. Browser sound requires a user interaction; the login and navigation controls prepare audio without playing a sound or asking for desktop notification permission. Closed apps do not play sounds.

Deploy both backend and desktop source when upgrading. On Render, keep the disk at /data, the existing owner and one instance. Enable Auto-Deploy → On Commit or select Manual Deploy → Deploy latest commit. After deployment, `/api/info` must report `realtimeSync: true`. Installing a desktop EXE does not deploy the Render backend. `node build/check-public-service.mjs --require-sync` verifies public metadata, chat, sign-in requirements and deployment of the recovery fix without creating accounts.
