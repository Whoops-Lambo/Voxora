Voxora 2.12.1 repairs the desktop update handoff and adds failure recovery.

- Voxora waits for the independent helper to verify the installer and installation access before closing. Startup errors/timeouts keep the app open with a retryable update.
- Explicit UTF-8 supports installation/cache paths with non-English Windows usernames. Spaces, apostrophes and wildcard characters remain literal paths.
- The helper waits for shutdown/file locks, verifies the installer again, checks installer exit status and the installed version, then requires confirmation from the relaunched desktop.
- Failed installations attempt to reopen Voxora. Relaunch failures show a Windows recovery dialog. Persistent local logs replace silently swallowed errors.
- The installer stops with an error when application files cannot be replaced. User chat data, login sessions, Plus subscriptions, settings and remote connections are preserved.

If your old updater closes Voxora without finishing, close Voxora and run the 2.12.1 installer manually once. Logs are in %APPDATA%\Voxora\updates\install-update.log and install-helper-output.log. The owner can request feed checks using Platform Admin → Updates → Notify Desktop Clients. Shared backends still require their own deployment.

Verification includes real PowerShell script tests with simulated Windows executables, covering success, Unicode paths, installation failure, wrong installed version, tampering after handoff, relaunch failure and missing executable. The unsigned Windows installer is built and archive-verified on Linux; native Windows installation/relaunch still requires validation on a Windows machine.
