Voxora 2.12.2 fixes an installer regression introduced in 2.12.1.

- NSIS file operations no longer inherit an error flag left by an earlier registry or installer-page operation. A successful copy cannot trigger the misleading "close Voxora" failure.
- Directory creation and file extraction have separate error checks. Real failures identify the affected path and mention permissions or file/security locks without claiming that Voxora is open.
- Compiled installer regression tests cover stale flags, clean installation, overwrite/reinstallation, genuine blocked folders and file locks, and preservation of unrelated files through install/uninstall.
- Native Windows builds preserve source paths and resolve the generated manifest and icons without mixing path separators.
- A Windows CI workflow builds and exercises the production installer, starts the installed desktop/backend, reinstalls, and uninstalls on an isolated Windows runner.

Install 2.12.2 manually if 2.12.1 refuses to install. Do not uninstall Voxora or delete its chat data to work around the false warning. The corrected installer supports the existing installation folder and preserves accounts, messages and preferences.

Windows validation passed for all three installer regressions and production install/UI startup/reinstall/uninstall: https://github.com/Whoops-Lambo/Voxora/actions/runs/41231795245. Linux verification also passed 58 backend/helper tests and the two desktop-update browser scenarios. The automatic-update helper itself still uses mocked executables in its PowerShell integration tests.
