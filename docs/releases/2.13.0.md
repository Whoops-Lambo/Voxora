Voxora 2.13.0 adds forum channels and corrects how desktop clients join a shared platform.

- New desktop installations open shared-server setup, with https://www.voxora.com as the planned address. An unavailable shared server no longer silently starts a separate local platform. Private workspaces require an explicit choice and retain earlier local data.
- Persistent installation IDs identify saved backends. Platform ownership is initialized once; later signups receive no platform administration. Private owners are labeled Workspace Owner rather than Voxora Owner.
- Searchable server member lists include offline people, live signup updates, and a Members dialog for small screens. Accounts on the same backend join the default Community; custom servers still require an invite.
- Forum channels provide titled posts, colored and required tags, attachments, threaded replies, search, sorting, unread filters and pagination. Moderators can pin, archive and lock discussions. Post edits detect stale revisions, and AutoMod checks titles and content.
- Selecting Do Not Disturb suppresses alerts immediately, including while profile/state responses are delayed. Status changes advance activity revisions so older snapshots cannot roll back Do Not Disturb.
- Bot SDK methods support forum listing, posting and editing with existing channel allowlists and server permissions. Server templates preserve forum layouts without copying discussions.
- Docker, Compose and Caddy configuration supports a shared backend with persistent data and HTTPS. See docs/SHARED-PLATFORM.md for setup and migration.

The www.voxora.com address still requires a hosted backend and DNS configuration. This release does not deploy that service. Everyone must connect to the same running backend to share accounts and memberships. Earlier independent local databases are preserved, not automatically merged.

Install the new Windows version over your existing installation. Use Voxora → Server Connection to select the shared address or explicitly reopen your old private workspace. Shared backends need their own source upgrade and restart using the same persistent data directory; updating a desktop does not deploy the hosted backend.
