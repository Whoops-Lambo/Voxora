Voxora 2.14.0 removes the domain requirement from setup, improves automatic update delivery and adds server nicknames.

- Open Local Workspace is the main setup action. No voxora.com address, DNS or hosted backend is required. Optional shared connections start with a blank address and retain saved configurations. Existing local accounts and messages are preserved.
- The Windows helper no longer uses the detached-process flag that can make PowerShell exit successfully without executing its script. Hash verification uses .NET SHA-256 directly, avoiding missing Get-FileHash modules in some Windows launch environments. The app still waits for verified helper readiness before closing. Install 2.14 manually once if an earlier helper cannot start.
- Updates check on startup and every minute, after waking/focusing the app and reconnecting. Failed checks/downloads retry with backoff beginning at 15 seconds. Feed requests bypass the mutable cache.
- If the primary download host fails, the updater resolves the exact public Git LFS object through the official repository. GitHub storage paths, expected size, Windows executable headers and SHA-256 are validated before an update becomes installable. Temporary signed URLs are not persisted or exported.
- Update availability, progress and failures appear outside Settings. Setup has update controls before login, and Copy Update Diagnostics supplies recent local update events without chat data or credentials.
- Server nicknames have self-change and moderator role permissions, hierarchy enforcement, reset, audit reasons and optimistic revisions. Names stay scoped to one server and appear in member search, messages and threaded replies. Removed members lose the nickname; a rejoin cannot apply stale edits.

Existing clients receive this as a newer release, rather than reinstalling the version they already have. Apps before 2.14 retain their earlier polling/retry behavior until upgraded; use the native Voxora → Check for Updates menu or the new installer if a previous updater cannot download. Restarting to install still requires your choice.

Local workspaces remain separate installations. People on different computers need one shared backend to share memberships. No specific domain is required, and existing private databases are not automatically merged. Desktop updates do not deploy a separately hosted backend.
