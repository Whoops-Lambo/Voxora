Voxora 2.15.1 fixes the install-confirmation race behind “Download and verify an update before installing.”

- A feed check no longer changes a verified, ready update into an unready state. Focus, resume and timer checks pause while the installation confirmation is open.
- The confirmation pins the exact release being approved. Late feed responses cannot replace it, clear readiness or reset an active installer handoff. Duplicate confirmation and install requests share one operation.
- Choosing Later or closing the confirmation preserves the verified installer and resumes automatic checks. Dialog failures and helper startup failures leave Voxora open with a retryable update.
- Installer size, executable header and SHA-256 are still checked immediately before launching. Corrupt cache files lose their ready status and are downloaded again; a new release cannot inherit approval given to a different release.

If your current copy shows this error, close Voxora and run the 2.15.1 installer manually once. The faulty confirmation handler is part of the installed desktop app, so downloading a new release alone cannot replace it. Local accounts, messages, saved connections and the navy/mint design are preserved. No domain is required.

Regression coverage reproduces the original error with a pending background check, holds confirmation open across focus checks, changes the available feed release, exercises Later, retries a failed dialog, combines duplicate clicks and tampers with the cache before approval. The Windows production smoke test now uses the same confirmation method as the app and injects pending-check/focus timing before its real installer handoff.

Validation passed: 83 applicable backend/helper tests, all three update browser scenarios and the [native Windows production run](https://github.com/Whoops-Lambo/Voxora/actions/runs/41372827481), including the confirmation/focus race, verified installer execution, relaunch, shared/local connections and data preservation. Windows also passed all 33 selected updater/installer regression tests. The older 2.15 helper is tested separately using the SHA-256-verified published installer; that compatibility handoff does not repair its known confirmation bug.
